# 用冻结方法定位一组新观测

`locate.py` 是项目的应用入口：读取新观测，校验科研运行已经冻结且证据与源码匹配，然后执行冻结数值方法。它不调用大模型、不重新调参，也不需要真实目标位置或场景标签。科研智能体负责发展并冻结方法；这里负责把已有方法应用于新的输入。

## 快速运行

在项目根目录执行：

```powershell
python locate.py --input examples/observations.json --run runs/live_reference --calibration results/benchmark/conformal.json --alpha 0.1 --output results/my_location.json
```

输出目录会在需要时创建，但不会覆盖已有结果文件。再次运行请换一个 `--output` 文件名；省略 `--output` 时将完整 JSON 写到标准输出。应用输出不得写入已保存的科研运行目录。

运行需要 `runs/live_reference/tools/frozen_method.json` 及其配套状态、协议与开发证据。未完成冻结时会明确报错，不以任意默认方法代替。入口调用 `benchmark.validate_frozen_run()` 检查冻结记录、方法注册表、开发实验摘要与源码 hash；这只是本地完整性校验，不是第三方签名认证。不要编辑已冻结的核心源码后继续声称使用同一研究结果。

## 输入只含四个观测数组

```json
{
  "anchors": [[0.0, 0.0], [6.0, 0.0], [0.0, 8.0]],
  "times": [-3.0, -2.0, -1.0],
  "ranges": [3.61, 5.0, 5.39],
  "sigma": [0.8, 0.8, 0.8]
}
```

| 字段 | 维度 | 含义与单位 |
| --- | --- | --- |
| `anchors` | n × 2 | 每条测距对应的接收点二维坐标，单位米 |
| `times` | n | 测量相对当前参考时刻的秒数，历史观测必须 ≤ 0 |
| `ranges` | n | 已反演或直接获得的距离，单位米，必须严格为正 |
| `sigma` | n | 该距离观测的测量尺度估计，单位米，必须严格为正 |

至少需要三条观测，四个数组必须逐条对应且长度一致。坐标使用同一局部平面坐标系；不要直接把经纬度角度填入米制坐标。绝对时间戳先减去希望估计位置的参考时刻，例如 `times_i = timestamp_i - reference_timestamp`；不要求最后一条测量恰好位于 0 秒。

这个入口处于距离观测层，不会从原始 RSSI 自动推导可靠距离或尺度。`sigma` 应来自可用的标定或测量质量估计，不能用实际误差或不可见真值构造。模型对信息不足的运动拟合可能退回静态模型，具体原因保留在 `diagnostics`；输入条数足够不等于几何可辨识。

**原论文公式勘误：**冻结的组合估计器在 `residual=range, scale=reported` 时实际使用 `q_i=max(sigma_i,1e-5)`，原论文的 `q_i=sigma_i` 漏写了该数值下界。`scale=constant` 且未显式提供常量时，使用施加下界后的尺度中位数。本说明仅针对组合估计器，不概括其他历史基线；代码、历史预测和校准没有因此改变。

输入严格拒绝额外字段，包括 `truth`、`velocity`、`scenario`、`meta`、异常点掩码和场景种子。求解器收到的是一个只有四个字段的观测对象。重复 JSON 键、NaN/Infinity、布尔值、数值字符串、嵌套向量维度错误、非正距离或尺度以及未来时刻都会被拒绝，不会悄悄转换或补齐。

`examples/observations.json` 是独立演示种子 `1949072381` 生成的 12 条合成观测，使用与最终测试协议不同的种子。文件仅保留四个观测数组，全部真实位置、速度、场景、种子和潜变量字段都已删除。它用于检查应用接口，不计入论文测试或证明真实现场性能。

## 输出如何理解

2026-10-12 起输出为 `schema_version=2`，新增独立数值筛查：先查看 `numerical_quality.passed`。失败时 `status=rejected_numerical_quality`，保留的点估计和半径只能用于诊断；通过时为 `estimated`。筛查检查求解状态、弱几何和重定坐标原点后的稳定性，不替换冻结估计值或校准。阈值、额外计算成本与局限见 [第二轮应用说明](application_revision.md) 和 [工程审查](QUALITY_REVIEW.md)。

- `position`：参考时刻 t = 0 的二维位置点估计，单位米。
- `velocity`：估计的二维速度，单位米/秒；静态模型通常返回零向量，不能据此直接证明目标确实静止。
- `selected_model`、`diagnostics`：选用模型、残差、保留观测、局部几何、求解状态与回退原因等实际诊断。
- `method_id`、`method_spec`、`run_integrity`：所用冻结方法和本地完整性检查结果。
- `observations.input_sha256`：实际送入求解器的输入字节快照 hash，读取与哈希绑定同一份数据；输出不需要也不推断真实位置。
- `calibration`：可选校准半径及其来源、假设和限制。

没有真实位置时，入口不能计算误差、正确率或“本次预测已被覆盖”的标签。即使数值求解成功，也可能存在镜像歧义、模型失配或校准偏移；这些问题应结合观测几何与外部领域证据判断。

## 可选校准半径

若 `--calibration` 指向的文件不存在，仍返回点估计，`calibration.status` 为 `not_found`，`radius_m` 为 `null`。因此可以在独立校准尚未完成时使用冻结点估计，但没有校准半径。

若文件存在，它必须与同目录 `protocol.json` 配套；入口核对其中的冻结记录 hash 和 `llm_selected` 方法定义，防止误用其他模型的分位数。`--alpha` 必须对应已保存的校准级别，例如 0.1 或 0.05，不进行分位数插值。入口还核对校准样本数与顺序统计量索引。

半径严格复用 benchmark 中的尺度规则：

```text
r(x) = q × g(x)
g(x) = benchmark.scale(本次预测)
```

其中 `q` 来自匹配级别的校准分位数，`g(x)` 来自本次观测产生的几何尺度代理，使用与校准相同的下界和非有限值回退规则。半径对应以 `position` 为圆心的圆盘。如果所请求级别没有有限分位数，则返回 `no_finite_quantile` 与空半径，不能伪造一个有限数值。

标称 `1−alpha` 是依赖校准/新样本交换性与同一冻结估计器的边际覆盖目标。程序无法仅凭四个数组验证现场分布符合这些条件，因此始终将 `coverage_guarantee_asserted_for_this_input` 与 `exchangeability_verified_for_this_input` 标为 `false`。这表示**没有对本次现场输入宣称覆盖保证**，不是断言本次定位一定错误。分布偏移、特定场景与拒识子集的覆盖不由该边际结论自动保证。

合成校准文件给出的半径不是原始 BLE 工业验收结果。现场应用需要独立的传感器标定、适当的现场校准样本，以及对建模假设的检验；本项目如实提供点估计与可审查的数值证据。
