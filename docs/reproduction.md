# 复现、数据隔离与统计指标说明

本文对应仓库中的 `run_agent.py`、`tools/toolkit.py`、`benchmark_v2_1.py`（正式入口）、`benchmark.py`（原校验/统计库）和
`localization/`。它说明如何重新运行和审查证据，不预先填写最终准确率、覆盖率
或优于基线的结论。正式数字应从对应运行目录的原始结果与协议文件读取。

## 1. 三种运行的区别

本项目区分真实大模型研究、决策回放和软件测试。

1. **真实研究**：外层 Python 控制器调用已配置的大模型 CLI，模型根据已返回的
   数值证据选择下一个研究工具。规划、假设修订、诊断、消融和冻结决策记录在
   `events.jsonl`。求解器执行已有的数学算子，不因此成为大模型，也不能声称
   这些预实现算子由模型发明。
2. **决策回放**：读取历史模型响应，重新执行对应工具。所有响应标记为 replay，
   不发生新的模型推理。这可审查数值计算和调度，不是新的独立科研试验。
3. **软件测试**：`tests/` 使用显式测试夹具、独立探针种子与小样本；它们不构成
   研究成绩，也不读取正式主测试集、校准集或覆盖率测试集。

相同数值输入、方法和软件版本应给出一致或数值容差内一致的定位结果。
真实大模型重新运行不保证提出相同方法。墙钟时间、时间戳、模型服务输出及其
衍生哈希通常不逐字节相同；不要把这些差异当作定位算法不确定性的证据。

## 2. 环境与依赖

在仓库根目录运行下列 PowerShell 命令。建议使用独立虚拟环境：

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

可选的 `requirements-lock.txt` 将参考数值依赖固定为 NumPy 2.3.5 与 SciPy 1.18.1；参考 Python 为 3.12.14，CLI 为 0.155.0-alpha.16.4。Python 与 CLI 不属于 pip 依赖，需单独准备。固定这些版本不等于固定远端模型的响应。

主数值依赖是 NumPy 和 SciPy。真实模型运行还要求本机已有可用并已认证的
Codex CLI；运行器沿用该 CLI 的模型配置，不在命令中指定模型名称。
如可执行文件不在 PATH，可在当前进程设置 `CODEX_EXECUTABLE` 为其绝对路径。
项目不读取或复制认证文件，也不应把认证信息提交到 GitHub。
报告构建依赖另列于 `requirements-report.txt`，不属于数值核心运行的前置条件。

具体模型标识只能以 `model_calls/*/metadata.json` 中 CLI 明确返回的信息为准。
未返回时保留 `null`，不能依据模型自述、界面名称或目录名称补猜。

## 3. 启动真实研究

以下参数显示的是程序默认预算，实际运行以该次 `state.json` 中的 identity
和事件记录为准：

```powershell
& .\.venv\Scripts\python.exe run_agent.py `
  --provider codex `
  --output runs/my_live_study `
  --timeout 300 `
  --reasoning-effort medium `
  --max-steps 26 `
  --max-experiments 10 `
  --max-model-calls 38
```

必须使用新的输出目录。单个实验工具调用最多评估四种方法；验证集最多允许
四次工具调用。`ablate` 也消耗实验预算。注册方法最多包含十六个新方法，
另外四个是预先声明的参考基线。每次注册执行一个无关种子的小型 API 探针，
只返回是否能调用，不把探针误差交给研究规划器，也不计入正式研究指标。

预算不是“所有方法耗费相同 CPU 时间”的保证：不同方法的 CV、子集初始化和
裁剪次数不同。数值结果同时报告求解器残差求值次数 `work_units` 和实际耗时。
完整工作量还包括规划器推理、注册探针、数学检查和优化器外部的残差评分；
这些不能用单一 `work_units` 全部代替。

每三个成功的 `run_experiment` 动作触发一次独立批评提示调用。批评者使用相同
配置模型承担另一角色，并不是另一个独立模型或独立经验复现。
`ablate` 消耗实验预算，但当前不计入这项“三次 run_experiment”触发计数。

模型失败最多重试两次，仍失败则保留状态并报错，不退回规则规划器。
工具失败作为失败观察进入记录，不自动盲目重做可能已有副作用的操作。

程序提示要求规划器只提交注册的研究工具动作。底层 CLI 请求只读沙箱，
运行器检测并记录已知的额外工具事件；这不是完全移除底层 CLI 工具的安全边界。
审查时应查看 `unexpected_tool_events`，不能只凭提示声称完全工具隔离。

## 4. 中断、恢复与回放

手动停止可在该次运行目录创建 `STOP` 文件：

```powershell
Set-Content -LiteralPath runs/my_live_study/STOP -Value 'Requested stop'
```

控制器在下一个模型或工具边界检查停止请求，正在执行的模型调用受单次 timeout
限制。恢复前移除这一个明确的 STOP 文件，然后沿用原 provider、全部预算、
配置和源码，增加 `--resume`。身份哈希不同会拒绝恢复；工具调用中断且副作用
不确定时也拒绝自动重放，必须先人工审查证据。

成功冻结后开发立即结束，恢复不会继续修改方法。不能通过恢复偷偷更换种子、
增加测试反馈或修改所选配置。

回放已保存的大模型响应：

```powershell
& .\.venv\Scripts\python.exe run_agent.py `
  --provider replay `
  --replay-source runs/my_live_study `
  --output runs/my_replay
```

若原运行使用了不同预算，应在回放时提供相同预算。默认回放记录提示哈希是否
相同，但不会仅因提示中的耗时或路径变化而拒绝；底层 `ReplayProvider` 支持
额外的严格提示检查。回放耗尽即失败，不自动追加新模型推理。

| 数据用途 | 根种子 | 场景及默认规模 | 能否用于修改方法 |
|---|---:|---|---|
| discovery | 46191 | 四个核心场景，各 16 例，共 64 例 | 可以 |
| validation | 57383 | 四个核心场景，各 24 例，共 96 例 | 可以，但最多四次工具调用 |
| 主测试 | 814711、826013、837901 | 每种子四个核心场景，各 30 例，共 360 例 | 不可以 |
| 压力测试 | 849391 | 五个压力场景，各 40 例，共 200 例 | 不可以 |
| 独立校准 | 862193 | 核心场景的均匀 iid 混合，共 240 例 | 只计算冻结尺度的分位数 |
| 覆盖率测试 | 875149 | 同一 iid 混合，共 320 例 | 不可以 |

四个核心场景为静态干净、静态异常、运动干净和运动异常。五个压力场景为
狭窄锚点几何、加速度运动、稀疏观测、标定偏移和高污染。
主测试与压力测试每类配额固定；校准与覆盖率测试每个案例都独立均匀抽取核心
场景，再抽取案例种子，因此每类实际数量通常不完全相等。

`cases_for` 只向研究工具开放 discovery 和 validation。所列后四类数据由
独立 `benchmark_v2_1.py` 在取得冻结方法后生成。正式种子与旧版研究的
development=1107、test=2209、stress=3313 不同，没有直接复用旧版根种子。
第二版研究动机可以来自旧版失败分析；这不等于第二版新测试集已被用于调参。
数据独立性还依赖实际运行纪律和日志审查，而不是只看种子数字。

冻结工具至少要求三个实验调用、两个新注册方法、一项诊断、一项数学检查，
且被选方法已有 validation 证据。研究目标还提出至少三个可检验假设、三个
有组成差别的方法及一次控制消融；这些较强要求要逐项审查真实事件，不能
仅凭 `frozen=true` 断言全部满足。

## 6. 独立评估命令

正式入口 v2.1 是研究未冻结、holdout 未生成前的代码审查修订，仅防止基线简称产生非法组件消融。原 `benchmark.py` 保留原字节作为初始化版本及共享库；不修改冻结哈希、不比较两个入口后择优。原快照、精确 diff 和新版哈希见 [修订说明](../research/evaluator_amendment.md)。

确认存在 `runs/my_live_study/tools/frozen_method.json` 后，使用新的结果目录：

```powershell
& .\.venv\Scripts\python.exe benchmark_v2_1.py `
  --run runs/my_live_study `
  --output results/my_benchmark `
  --main-per-scenario 30 `
  --stress-per-scenario 40 `
  --calibration-size 240 `
  --coverage-size 320
```

评估包括四个预声明基线、冻结方法、适用的组件消融，以及研究中最早注册的
两个前驱方法（与冻结规格相同的前驱会跳过）。消融项根据冻结方法的组成
机械生成，不根据测试分数重新选择。即使某个消融在测试集更好，也不应把它
事后改称原先选定方法；应保留这一负面结果。

生成案例、方法字典、软件版本与源码哈希写入 `results/.../protocol.json`。
每个方法在同一个 split 上使用完全相同的案例。每种方法的逐例预测和指标
保存为独立 JSON；汇总 CSV 记录误差、估计坐标、工作量和耗时。
校准预测、覆盖率预测和 conformal 结果单独保存。

若只做运行速度检查，请使用新的演练目录与明确标注的演练样本量，不得把
缩小样本的结果混入正式结果，也不要看过正式结果后再修改冻结方法。
本文不执行任何正式评估，也不提供未运行的数字。

## 7. 定位指标和成对区间

逐例定位误差是 `e_i = ||estimated_position_i - truth_i||_2`，单位为米。
真值只由评价器读取；求解器、初始化、CV 子集和共识评分只读四个观测数组。

- 均值：所有案例的平均误差。
- RMSE：`sqrt(mean(e_i^2))`，对大失败更敏感。
- 中位数、P90、P95：经验误差分位数。
- 最大值：本次有限样本中最坏误差，不是理论上界。
- 5 m / 30 m 内比例：经验事件 `e_i <= threshold` 的比例。
- 宏平均误差：先求各场景平均误差，再对场景等权平均，避免案例数不等时由
  样本多的场景主导。在各类例数相同的主测试中，它与总体平均相等。
- 平均工作量：所有优化器的真实残差求值次数均值，包含 CV、随机子集、裁剪
  和完整重拟合；它不是总浮点运算量。

成对 bootstrap 先按 `case_id` 对齐冻结方法与比较方法，定义差值
`d_i = reference_error_i - selected_error_i`。正数表示冻结方法误差更低。
在每个场景内对案例成对、有放回抽样，然后对场景均值等权平均，共 3000 次，
取第 2.5% 和 97.5% 分位数。
该区间描述固定方法在当前合成分布下的案例抽样不确定性，不覆盖大模型搜索
随机性、真实无线电分布或先前研究设计选择的不确定性。多个比较没有进行
多重比较校正，不能把所有单项 95% 区间组合成联合 95% 保证。

## 8. Split conformal 的精确定义与限制

冻结方法对每个案例输出位置估计和正的可观测尺度 `g_i`。
`g_i` 来源于数据残差 Jacobian 及绝对残差的局部几何代理，范围截在
0.2–100 m；退化情形给出保守上限。它本身不是置信区间、概率保证或完整
Fisher 信息结论，局部满秩也不能排除全局镜像歧义。

独立校准集大小为 m，校准分数为

```text
S_i = e_i / g_i
k = ceil((m + 1) * (1 - alpha))
q = 第 k 小的校准分数；若 k > m，则 q = +∞
新案例半径 R(x) = q * g(x)
```

这里使用有限样本阶数，不使用线性插值的普通经验分位数。圆盘中心是冻结的
定位估计。程序分别计算 alpha=0.10 和 alpha=0.05。
当定位器与尺度函数都在独立校准前冻结，校准案例与一个新案例可交换时，
标准 split-conformal 结论是**边际覆盖率至少 1-alpha**。独立均匀场景混合
用于使校准和覆盖率测试来自同一分布，而不是把固定每类配额误称 iid。

报告中的有限测试集经验覆盖率仍会随机波动，不必每次都高于名义水平。
该保证不自动推出某一个场景的条件覆盖率、分布偏移后的覆盖率，或按半径
拒绝部分案例之后的条件覆盖率。

拒绝曲线使用预声明半径阈值 2、5、10、15、20、30、50 m，接受 `R <= threshold`
的案例，分别报告接受比例、接受数、接受后平均误差及经验覆盖率。
没有接受案例时相关均值与覆盖率是 `null`，不是零。
半径小的案例仍可能因模型偏差而集中失效，不能把“拒绝大半径”直接当作
“剩余案例具有名义覆盖保证”。压力集结果同样只作经验外推检查。

当校准规模太小导致 q=+∞ 时，内部数学定义正确地给出无限半径；通用 JSON
清理会把无限数写成 `null`。审查此类小样本演练应结合 `order_statistic_k`
与 `calibration_n` 识别这一情况，不把 `null` 误解为半径零。默认校准规模
240 不触发这一边界。

## 9. 证据目录、校验与当前审计限制

建议先保存完整运行目录，再整理报告：

| 文件 | 作用 |
|---|---|
| `protocol.json` | 开发种子、数值/工具/运行器/研究入口/评估入口源码哈希及目标摘要 |
| `state.json` | 控制器身份、预算、长期记忆、冻结状态 |
| `events.jsonl` | 请求、响应、动作、工具结果和批评的哈希链 |
| `model_calls/` | 原始提示、schema、模型响应、CLI 事件及元数据 |
| `tools/tool_state.json` | 不可重名注册方法、开发评价目录与计数 |
| `tools/frozen_method.json` | 冻结规格、验证证据、科学结论与注册表哈希 |
| `results/.../protocol.json` | 正式评估的独立种子、样本量、方法和源码哈希 |

最终研究前的协议检查已加入以下约束：

1. 每个实验调用使用唯一编号路径，例如
   `experiments/call_003_validation_method.json`。同方法、同 split 重跑也保留
   两份独立证据；已有路径拒绝覆盖。方法目录指向最新一次评价，历史路径与
   哈希仍可由事件记录追溯。
2. 实验调用在数值计算前持久化已消耗预算。后续数值失败不会让恢复后的运行
   回收这次尝试的编号或验证预算。无效方法名称、重复名称和非法 split 在
   实验开始前拒绝；控制器的尝试计数可能包含这些失败动作，应区分两种计数。
3. `benchmark.validate_frozen_run` 在生成任何 holdout 数据前，要求控制器和
   工具状态均已冻结，冻结对象与控制器保存记录一致，所选方法与注册表一致，
   注册表哈希有效，并有一致的 validation 证据。
4. 该检查还比较初始化协议与控制器记录的 source_hashes，要求覆盖全部
   `localization/*.py`、`tools/*.py`、`agent_runtime/*.py`、`run_agent.py` 和
   `benchmark.py`，逐项校验当前文件。源码更改后，旧研究不能直接进入正式
   holdout；应开启新版本研究，不能仅重写旧协议哈希绕过检查。
5. 当前工具索引中每份评价的逐例文件摘要必须等于 `evidence_sha256`，指标
   摘要也必须与逐例文件保存的指标一致。检查结果写入正式 protocol 的
   `pre_holdout_integrity_check`。已被后续重跑替代的旧索引仍在事件中，但
   此入口不会自动遍历全部历史事件重新验证每份旧文件；需要完整历史审计时
   应结合事件哈希链及相应文件逐条检查。
6. 评价器保留新方法和旧基线的 `selected_model`，用于可验证的模型选择频率。
   如任何未知或外部方法缺失该标签，应显示 `unknown`，不能推断为静态。

这些是防止意外修改、证据覆盖和错误恢复的本地完整性检查，不是带外数字签名，
也不能抵抗同时重写所有本地记录的攻击者。完整交付仍宜固定整个提交或压缩包
的校验值，并保留原始模型调用和测试前冻结记录。若修改实现，应使用新的明确
版本和运行目录，避免在同一研究记录中悄然更换协议。

## 10. 测试与论文对应

`tests/test_localization.py` 检查解析 Jacobian、稳健损失与二次正则、对数校正
方向、无真值访问、观测层 CV 隔离、工作量计数、数据种子及压力参数。
`tests/test_runtime.py` 使用明确标注的假模型夹具检查实际模型驱动接口、失败
重试、预算、回放、恢复及哈希链；这些夹具绝不冒充模型研究记录。
`tests/test_study.py` 检查校准阶数、无限半径边界、尺度不变性、拒绝覆盖与
总体覆盖的区别、iid 抽样接口、成对场景统计、方法注册和冻结边界。

数学实现的精确目标函数、初始化、固定预算裁剪、CV 内部预算及数值局限见
`localization/method_math.md`；理论背景和适用条件见 `docs/research_context.md`。
论文中的每个数值表格应指向该次实际结果文件；实现测试通过不能替代研究
假设的实证验证，更不能证明原始工业开放问题已经解决。
