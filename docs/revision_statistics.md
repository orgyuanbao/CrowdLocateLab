# 第二轮独立评价与统计解释

本轮是承认第一轮失败后的再研究。第一轮测试结果属于已知先验，不能再次称为未见数据，也不能把两轮中更好的数值拼成同一个实验。`research/revision_plan.json`在第二轮智能体启动前登记；研究初始化清单同时锁定该计划、求解器、智能体和新评价代码。`benchmark_revision.py`只在控制器与工具均冻结、选定方法与登记/验证证据一致、全部源哈希一致时才生成新数据。旧源文件保持原字节。

## 数据与配对

主测试为三个全新根种子，每种子四个常规场景各60例，共720；压力五场景各80例，共400；边界为n=6..12与静止干净/移动干净两个场景的14个单元，各30例，共420。所有方法用完全相同的案例对象。案例ID包含split、根种子和顺序号，原生成标识仍保存在meta；评估标签和真值仅参与误差统计，不传入估计器或分组函数。

四个旧基线、第一轮冻结方法、第二轮冻结方法以及预定K3、K4、强制恒速、强制静止对照一起评价。K3/K4仅在最终方法本身是CV时可称为折数消融；否则同时启用了模型选择。标准化默认参数后完全重合的方法标记alias并复用同一预测，不增加独立方法证据。旧基线实现与新组合求解器即便目标相近也不随意合并。旧基线工作量是求解器nfev，新组合求解器工作量是包含CV等步骤的残差调用数；口径并不完全相同，不能把比值直接称为加速比。墙钟时间是本次机器上的观测，非严格控制的速度试验。alias时间来自原计算，不能视为另一次计时。

配对端点为参照方法误差减去第二轮方法误差，正值有利于第二轮。主测试按根种子×场景、压力按场景、边界按n×场景分层；各固定单元内重抽相同的案例索引，4000次，等权汇总单元均值，给出百分位95%区间。输入按case_id对齐并拒绝重复/缺失/错位。它估计固定设计中案例抽样的不确定性，不包含智能体搜索、选择或研究者决策的不确定性；大量方法和场景比较未校正多重性，属于探索性推断。原始场景、尾部、成本和三根种子结果全部保留；三个根种子是数据批次，不是三个独立智能体研究复现。

静止干净场景的预定容忍界是WLS平均误差的1.10倍，同时报告均值比、其配对bootstrap区间，以及平均差额`selected - 1.10*WLS`的区间。点估计满足该界与区间上界低于零分开报告。这里使用双侧95%近似区间，未校正多重性，不能包装为确认性非劣试验。

## 全局与Mondrian共形区域

只对第二轮冻结定位器做区域试验。校准800例、独立覆盖检验1200例，各自独立从四个CORE场景中逐例均匀抽取场景，故场景数随机；这与主测试的固定平衡配额不同。估计器、正尺度g(X)及分组h(X)在校准前冻结。分数为`S=||x_hat(X)-truth||/g(X)`。g沿用已冻结的观测Jacobian代理尺度与其截断/退化回退，不被称为已校准标准差。

全局区域用全部m个校准分数的第`k=ceil((m+1)*(1-alpha))`小值q，半径qg(X)。Mondrian使用`h(X)=static/velocity`，只读取定位器的观测选模诊断；旧标签dynamic映射为velocity，未知标签直接报错，不读取真实场景、真速度或误差决定分组。各组独立使用其样本数m_h和相同的m_h+1秩规则。组为空或k>m_h时q=正无穷；输出中使用字符串`infinity`和`unbounded`/`unbounded_n`明确记录，有限半径拒绝阈值不接受无界区域。绝不把无穷序列化为null后当作有限成功。

固定h、估计器与g，并假定校准和测试IID：给定测试点属于组h及该组校准样本数m_h，组内校准分数与一个新分数可交换，测试分数的秩给出至少1-alpha的覆盖。这里对校准分数的随机性取平均；不是给定已经实现的整份校准数据后的覆盖下界。连续分布可以得到更精确的秩等式，ties时标准非严格覆盖是保守的，不要求把连续性强加为最低条件。参考Vovk (2012) 第4节、命题3：<https://proceedings.mlr.press/v25/vovk12/vovk12.pdf>。真实场景不是h，所以按真实场景报告的覆盖不自动得到Mondrian保证；按半径拒绝后的子集也不继承保证。压力及n边界来自改变后的分布，均只报告经验表现。

独立IID覆盖集的总体、真实场景子群、观测选模子群附Wilson95%区间。它们针对固定本次校准规则以后，再抽取IID测试点的覆盖概率，条件于相应子群成员身份和已观测子群数。这是测试抽样区间，不是共形定理、校准重抽区间或工业验收保证。固定平衡且分布偏移的压力/边界混合不提供合并二项Wilson区间。半径拒绝曲线报告接受率、接受后覆盖与误差，拒绝子集不被称为条件覆盖保证。

## 运行与证据

在项目根运行`python benchmark_revision.py --validate-only`先只检查冻结完整性；正式运行`python benchmark_revision.py --run runs/revision_reference --output results/revision_benchmark`。固定方案没有样本量/种子覆盖选项，已有输出目录会被拒绝。成功时保存protocol、全部输入、每个方法的main/stress/edge预测、校准/覆盖预测、共形明细、比较、CSV和完成标志；失败也保留状态，不覆盖失败尝试。没有在冻结前运行这些正式种子的数值试验。

`revision.report.render(summary)`只读取完成的真实汇总生成LaTeX文字与H定位表格，可由外层报告生成器调用。若独立使用：`python -m revision.report --results results/revision_benchmark/summary.json --output latex/sections/revision_results.tex`。它不会修改原main.tex或制造尚不存在的成绩。
